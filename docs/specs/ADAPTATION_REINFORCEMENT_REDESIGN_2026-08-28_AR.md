# إعادة تصميم التكيف والتقوية — 2026-08-28

**الحالة:** مرجع صيانة معتمد للمراجعة، مع وجود قرار واحد يحتاج تثبيتًا نهائيًا: إلغاء الخفض التلقائي.

## 1. الهدف

فصل ثلاثة مفاهيم كانت مختلطة:

1. Placement بعد الاختبار القبلي.
2. Learning Adaptation أثناء النشاط.
3. Level Transition بعد إكمال المستوى.

## 2. Placement

الاختبار القبلي 30 سؤالًا / 100 درجة، موزعة 20/40/40:

- الاستعداد للقراءة: 20.
- بناء الكلمة وقراءتها: 40.
- الطلاقة والفهم: 40.

قواعد البداية:

- L1: أقل من 50 أو الاستعداد أقل من 12/20.
- L2: 50–79 أو فشل بوابة قراءة/بناء الكلمات.
- L3: 80+ مع اجتياز بوابات القراءة الأساسية ودقة مناسبة للنص.

التنفيذ يجب أن يكون Placement Engine مستقلًا. لا تعتمد النسبة العامة وحدها إذا فشلت بوابة حرجة.

في وضع `HIMMA_TEMP_AUDIO_SKIP=true`، أي Placement يعتمد على Evidence صوتي مفقود يجب وسمه Provisional/تجريبيًا، لا اختراع تقييم صوتي.

## 3. الرحلة بعد Placement

Placement يحدد نقطة البداية فقط:

- L1 → L2 → L3 → Posttest.
- L2 → L3 → Posttest.
- L3 → Posttest.

لا يجوز فتح Posttest لمجرد إكمال L1 أو L2.

## 4. نتيجة النشاط الفورية

- 80–100: PASS → النشاط التالي.
- 70–79: GUIDED_RETRY → إعادة الجزء الخاطئ/محاولة موجهة، وليس نشاط تقوية كاملًا فورًا.
- أقل من 70: WEAKNESS_EVENT → تقوية موجهة للمهارة.

## 5. بعد التقوية

المسار الإجباري:

`Core weakness → Reinforcement → Return to failed core step/activity → Verification → Continue`.

لا تعتبر التقوية نجاحًا نهائيًا للمهارة بدون تحقق من الأصل.

إذا فشل الطالب بعد دورة تقوية محدودة، يمنع loop لانهائي ويظهر تدخل مشرف موثق.

## 6. Mastery 50/30/20

آخر ثلاث محاولات صالحة تظل مؤشرًا مهمًا:

- الأحدث 50%.
- السابق 30%.
- الثالث 20%.

لكن تستخدم كـSkill Mastery/Trend، ولا تسمح بتخطي بقية أنشطة المستوى.

## 7. Level Completion Gate

الانتقال للمستوى التالي يحتاج:

- 10/10 Core activities للمستوى مكتملة.
- لا Reinforcement gap معلقة.
- تغطية المهارات المطلوبة.
- لا مهارة حرجة غير معالجة.

الكود الحالي بعد سلسلة commits 2026-08-28 بدأ يطبق شرط 10/10 ويفتح Core Session جديدة للمستوى التالي، وهذا اتجاه صحيح يجب الحفاظ عليه.

## 8. جلسات المستوى

المطلوب تاريخيًا واضح:

- Core Session مستقلة لكل مستوى.
- عند الانتقال يغلق مستوى Lx ويفتح session جديدة Lx+1.
- لا تُعاد تسمية جلسة L1 تاريخيًا إلى L2 أو L3.
- Reinforcement يبقى داخل مستوى الطالب الحالي.

## 9. الخفض التلقائي — قرار صيانة يحتاج تثبيتًا نهائيًا

المتطلبات القديمة تسمح بخفض بعد قرارين منخفضين متتاليين.

المراجعة الجديدة توصي:

- لا Automatic Demotion في الرحلة العادية.
- نقطة البداية تحدد مرة بالقبلي.
- الأداء المنخفض يعالج Guided Retry + Reinforcement داخل المستوى.
- إذا ظهر تعثر شديد ومستمر، يتدخل المشرف يدويًا بسبب موثق.

**لا تحذف demotion من الكود قبل تسجيل ADR نهائي واعتماد هذا القرار.**

## 10. Reinforcement Mapping

المشكلة الحالية: Exact `skill_id` أضيق من بنية المحتوى.

المطلوب:

`Skill → Skill Family → Approved Reinforcement Candidates`.

Metadata الموصى بها:

- `target_skill_family`
- `target_skills`
- `severity`
- `requires_audio`
- `success_threshold`
- `max_retries`
- `return_to_core_activity`
- `verification_required`

أي Mapping غير معتمد يبقى Safe Hold ولا يتحول إلى نشاط عشوائي.

## 12. واجهة الطالب

الطفل لا يرى:

- mapping gap.
- mastery percentages التشخيصية.
- weakest_skill.
- قرار المشرف التقني.

يرى لغة مثل:

- «لديك تدريب قصير يساعدك أكثر في هذه المهارة».
- «ممتاز، أصبحت جاهزًا للعودة إلى مسارك».
- «رائع، أنت مستعد للخطوة التالية».

## 13. واجهة المشرف

يجب عرض:

- نقطة البداية.
- المستوى الحالي.
- L1/L2/L3 status/progress.
- أضعف مهارة ودليلها.
- آخر نتيجة.
- حالة التقوية.
- نشاط التقوية.
- العودة إلى أي نشاط أساسي بعد التقوية.
- سجل القرارات والتجاوزات.

## 14. اختبارات إلزامية

- Placement boundary tests للـ20/40/40 والبوابات.
- 79.99 لا يساوي 80.
- 69.99 يدخل reinforcement.
- 70–79 Guided Retry.
- لا promotion قبل 10/10.
- L1→L2، L2→L3، L3→journey complete.
- reinforcement ثم core verification.
- no random reinforcement.
- no infinite reinforcement loop.
- temporary audio evidence neutral.
- manual override audited.
